# Enforce orphan-only deletion at command execution

Maintainer direction, 2026-10-14. The orphan browser in
`curriculum-restapi` lists orphaned entities, lets an editor select them, and
sends `deleteEntity` changes with `orphanOnly: true`. The maintainer recalled a
matching store-side guard, asked whether it had ever been implemented, and—after
the investigation showed it existed only as an uncommitted prototype—directed:
"Lets do that".

At the current `curriculum-store` `main` base (`05ad3e7`), command execution
ignores `orphanOnly`. That creates a time-of-check/time-of-use gap: an entity can
gain a parent after the browser lists it but before the deletion command runs.
The REST API would still report the deletion as successful.

Requested behavior:

- before applying any change in a command, revalidate each `deleteEntity`
  change carrying `orphanOnly: true` against the current store state;
- accept only existing entities whose schema type exists, is not a schema root,
  is neither `KerndoelUitstroomprofiel` nor `Deprecated`, and has no current
  `root` link;
- reject the entire command before mutation when any selected entity no longer
  satisfies those conditions;
- preserve ordinary `deleteEntity` behavior when `orphanOnly` is absent;
- keep the existing soft-deletion representation and restart persistence; and
- make query memory configurable, with the current 64 MB effective default, so
  deployments can raise it for large orphan scans.

Evaluation requires focused unit coverage for accepted and rejected entity
classes, atomic rejection of mixed selections, stale-listing revalidation, and
ordinary deletion compatibility. A runtime test must show a guarded deletion
persists through restart. The existing test suite should pass with coverage
collection disabled; the repository's known coverage-threshold and missing
ESLint-configuration issues are not part of this request.

Generated dataset/schema changes from the old working tree, UI work, changing
the orphan definition, hard deletion, and unrelated cleanup are out of scope.
