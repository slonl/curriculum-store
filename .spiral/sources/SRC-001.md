# Source: NiveauIndex Invariant Clarification

## Source Kind

Connected conversation.

## What Was Actually Expressed Or Observed

The maintainer clarified the intended purpose and behavior of `NiveauIndex`:

- `NiveauIndex` exists as an efficient way to filter entities on materialized
  `Niveau`.
- Entities form a graph, and not all entities have `Niveau`.
- If a child entity has `Niveau`, it should also have that value in
  `NiveauIndex`.
- Parent entities should collect niveau references from children, unless the
  parent has its own `Niveau` list.
- A parent with its own `Niveau` list uses that list as authoritative for
  `NiveauIndex` from that point upwards.
- `NiveauIndex` should be de-duplicated.
- `Vakleergebied` should not be treated as a child relation for this purpose;
  it is a related relation and should not create parent links.
- `NiveauIndex` is always derived data. During `create`, do not use existing
  `NiveauIndex` as source state. During `update`, existing `NiveauIndex` may be
  used as a performance shortcut when possible.

The maintainer also corrected an earlier interpretation: the existing failing
regression tests in `test/niveau-create-regression.mjs` had already been
investigated and their assumptions about intended behavior were judged
incorrect. They should not be treated as evidence of the actual bug.
